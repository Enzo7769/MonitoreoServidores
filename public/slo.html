¿Qué es el SLO y el presupuesto de error?

SLO es el objetivo de disponibilidad de cada API en el mes (por ejemplo 99,5 %). Ese objetivo deja un presupuesto de error: la caída permitida. Con 99,5 % en un mes de 30 días son 3 h 36 min; cada falla lo va gastando.

El burn rate dice a qué velocidad se gasta: 1× significa que se agota justo al terminar el mes; 6× en ~5 días; 14,4× en ~2 días. Se alerta cuando el ritmo pone en riesgo el objetivo, no por cualquier falla aislada.

Los objetivos se configuran en servidores.json: "slo": { "objetivo": 99.5, "porServicio": { "APITicket": 99.9 }, "porServidor": { "torax": 99.9 } }. Las fallas durante una mantención no gastan presupuesto.
